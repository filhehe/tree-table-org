# 002. SSE вместо WebSocket и поллинга

- Status: Accepted
- Date: 2026-09-15
- Tags: realtime, transport, nginx
- Relates: [architecture.md](../architecture.md), [data-model.md](../data-model.md), [001-swr-cache-layer.md](001-swr-cache-layer.md)

## Контекст

Cервер шлёт обновления в реальном времени.

Требования:

- патч без полного рефетча;
- индикатор соединения;
- экспоненциальный backoff при обрыве.

Поток данных односторонний: сервер → клиент, только `OrgPatch`.
В production nginx проксирует API и отдаёт статику. Нужен транспорт, который просто проксируется, контролирует reconnect и не провоцирует GET `/api/org-tree` на каждый тик.

## Решение

**SSE** по `GET /api/org-tree/stream`.

Клиент: **`fetch` + `ReadableStream`**, не `EventSource`.

Почему не `EventSource`:

- собственный reconnect не экспоненциальный (браузерный алгоритм фиксирован);
- сложнее единообразно выставить статус `reconnecting` / `offline`;
- в некоторых окружениях хуже контроль abort.

Почему `fetch` SSE:

- тот же AbortController, что у GET дерева;
- backoff полностью наш: `1s → 2s → 4s → …` cap **30s**, сброс на успешное событие или открытый поток;

Сервер:

```
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```

Кадр:

```
id: 42
event: patch
data: {"id":"…","budget":1000,"updatedAt":"…"}

```

Heartbeat: SSE-комментарий каждые 15 с, чтобы nginx/прокси не закрыли idle. Nginx: `proxy_buffering off;` на `/api/org-tree/stream`, таймауты чтения увеличены.

Индикатор шапки:

| Статус         | Когда                                                               |
| -------------- | ------------------------------------------------------------------- |
| `live`         | поток открыт, данные или heartbeat идут                             |
| `reconnecting` | ошибка/close, ждём backoff                                          |
| `offline`      | несколько неудач подряд (порог: 5) или `navigator.onLine === false` |

Вернувшийся `live` **не** делает полный GET, если в кэше уже есть snapshot. Первичные данные по-прежнему из `GET /api/org-tree`. SSE — только дельта.

## Альтернативы

| Вариант       | Почему нет                                                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| WebSocket     | Тяжелее, больше кода ping/pong. Имеет смысл, если появятся двусторонняя связь.                                                                         |
| Поллинг `GET` | Либо полный snapshot (против «без рефетча»), либо `?since=` (свой протокол дельт, сложнее SSE). Даже с backoff это лишние запросы при редких мутациях. |
| EventSource   | Мало контроля backoff; достаточно для демо, недостаточно, чтобы показать «эффективный reconnect».                                                      |

## Последствия

Положительные:

- Один направление, один MIME-тип, простой docker/nginx.
- Патч-контракт совпадает с доменом ([data-model.md](../data-model.md)).
- Backoff и индикатор — явные, как просит ТЗ.

Отрицательные:

- Нет реплея пропущенных событий (v1). После долгого offline дерево может расходиться с сервером, пока SWR (5 с stale) не подтянет snapshot на следующем «старении».

**Смягчение:** при переходе `offline` → `live` после N неудач **или** если разрыв длился > stale time, сделать один GET и заменить snapshot, затем снова патчи. Это не «рефетч на каждый патч», это recovery. Порог: разрыв ≥ 5 с.
